TaskFlow IA · Diagramas de secuencia

Qué ocurre, en orden, al crear, completar y eliminar una tarea. Son diagramas de la arquitectura propuesta (backend, PostgreSQL, n8n y servicios externos).

1. Crear una tarea

El usuario recibe respuesta en décimas de segundo; todo lo demás ocurre después, en paralelo.

sequenceDiagram
  autonumber
  actor U as Aurora
  participant UI as Interfaz
  participant API as Backend
  participant DB as PostgreSQL
  participant N as n8n
  participant S as Slack
  participant G as Google Calendar
  participant C as Claude
  U->>UI: Pulsa Guardar tarea
  UI->>API: POST /tasks
  API->>DB: Transaccion: tarea + asignado + eventos pendientes
  DB-->>API: OK
  API-->>UI: 201 Created
  UI-->>U: Fila nueva y contadores actualizados
  API-)N: Webhook task.created y task.assigned
  par Aviso al responsable
    N->>DB: Lee tarea y preferencias
    N->>S: Mensaje directo a Leo
    N->>DB: Inserta notificacion
  and Calendario
    N->>G: Crea evento de dia completo
    G-->>N: ID del evento
    N->>DB: Guarda vinculo task_calendar_events
  and Inteligencia artificial
    N->>DB: Comprueba limite diario y crea sugerencia pending
    N->>C: Tarea como datos, pide JSON
    C-->>N: Subtareas y prioridad
    N->>DB: Guarda respuesta ai.suggestion_ready
    N-)UI: Aviso: tienes una sugerencia
  end
  N->>DB: Marca eventos como procesados

2. Marcar una tarea como completada

Los recordatorios futuros dejan de afectarla porque consultan solo tareas sin completar.

sequenceDiagram
  autonumber
  actor L as Leo
  participant UI as Interfaz
  participant API as Backend
  participant DB as PostgreSQL
  participant N as n8n
  participant S as Slack
  participant G as Google Calendar
  participant GH as GitHub
  L->>UI: Elige Completada
  UI->>API: PATCH /tasks/128
  API->>DB: Transaccion: status y completed_at, eventos pendientes
  DB-->>API: OK
  API-->>UI: 200 OK
  UI-->>L: Contadores actualizados
  API-)N: Webhook task.status_changed y task.completed
  par Aviso al creador
    N->>DB: Registra el cambio en el historial
    N->>S: Aviso a Aurora: tarea completada
    N->>DB: Inserta notificacion
  and Limpieza de integraciones
    N->>DB: Lee vinculo de calendario
    N->>G: Marca el evento como completado
    N->>DB: Busca issue vinculado
    alt Hay issue
      N->>GH: Cierra el issue
    else Sin issue
      N->>N: Omite el cierre
    end
  end
  N->>DB: Marca eventos como procesados

3. Eliminar una tarea

Antes de borrar se guardan el ID del evento y el issue en el payload, porque el borrado en cascada destruye esos vinculos.

sequenceDiagram
  autonumber
  actor A as Aurora
  participant UI as Interfaz
  participant API as Backend
  participant DB as PostgreSQL
  participant N as n8n
  participant G as Google Calendar
  participant GH as GitHub
  participant S as Slack
  A->>UI: Pulsa la papelera
  UI-->>A: Dialogo de confirmacion
  A->>UI: Confirma
  UI->>API: DELETE /tasks/131
  API->>DB: Lee ID de evento de Calendar e issue vinculado
  API->>DB: Borra la tarea y la cascada elimina comentarios, adjuntos y vinculos
  DB-->>API: OK
  API-->>UI: 204 No Content
  UI-->>A: La fila desaparece
  API-)N: Webhook task.deleted con los datos guardados
  par Calendario
    N->>G: Borra el evento
    G-->>N: OK o 404 que se acepta
  and GitHub
    N->>GH: Comenta y cierra el issue 45 como no planeado
  and Aviso
    N->>S: Avisa a los responsables
  end
  N->>DB: Marca el evento como procesado
  Note over N,DB: Los archivos fisicos de adjuntos los limpia el mantenimiento del domingo

4. Caso con error: token de Google revocado al eliminar

Un fallo externo no bloquea al usuario ni a los demas pasos: queda pendiente y se reintenta al reconectar.

sequenceDiagram
  autonumber
  actor A as Aurora
  participant API as Backend
  participant DB as PostgreSQL
  participant N as n8n
  participant G as Google Calendar
  participant GH as GitHub
  participant M as Correo
  A->>API: DELETE /tasks/131
  API->>DB: Guarda payload y borra la tarea
  API-->>A: 204 No Content
  API-)N: Webhook task.deleted
  N->>G: Borra el evento
  G--xN: invalid_grant, token revocado
  N->>DB: Pausa la integracion del usuario
  N->>M: Vuelve a conectar Google Calendar
  N->>GH: Cierra el issue 45
  GH-->>N: OK
  N->>DB: Evento parcialmente procesado, paso de Calendar pendiente
  Note over A,N: Cuando Aurora reconecte, se reintenta el borrado pendiente
  A->>API: Reconecta Google Calendar
  API-)N: Webhook integration.connected
  N->>G: Reintenta el borrado pendiente
  G-->>N: OK o 404
  N->>DB: Evento completamente procesado
